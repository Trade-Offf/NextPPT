# 动效提示词层补全计划

## Summary

NextPPT 的核心叙事是"HTML 是下一代展示容器——保留动画和交互",但模版库的所有 HTML sample 和 prompt 都是纯静态的,形成 say-do gap。本计划通过两条路径补全动效能力:① 给旗舰 kami 模版补动效层(HTML sample + prompt)作为门面验证,② 给 guide 页通用 prompt 补动效指导段,让用户生成的 HTML 也能带动效。技术路线为 CSS 优先 + 轻量 vanilla JS(IntersectionObserver ~40 行),不引入外部库,确保编辑器兼容性和 AI 生成稳定性。

## Current State Analysis

### 产物矛盾
- 11 个模版全是 HTML(非 PPTX),但 **零动画、零交互、零 JS**
- 首页 hero 写"保留动画和交互",HTML 演示台能力卡片第一条是"JS、过渡、滚动效果照常运行"
- 模版库作为第一转化面,完全没有展示这一差异化能力

### Prompt 现状(两套互不重叠)
1. **通用 prompt** (`i18n/locales/zh/prompt.ts` 的 `generate`):guide 页使用,30 行,只规定静态视觉规范,零字提动效
2. **风格化模版 prompt** (`data/templates.ts` 里每个 `TemplateItem.prompt`):模版详情页使用,kami 的 prompt 有 127 行 8 章节,通篇静态视觉规范,末尾 Anti-Patterns 也全是静态规则

### kami-nextppt-deck.html 结构
- 14 个 `<section class="slide">`,固定 1280×720,body 用 flex 纵向排列(gap:24px)
- 纯静态:无 `<script>`、无 `@keyframes`、无 `animation:`、无 `transition:`、无 `:hover`
- 封面有"匠心之轮"SVG(同心圆 + 刻度 + 径向线 + 中心光晕 + 数据标注),是最佳动效载体
- 内含 21 个 SVG 图表(架构图/流程图/折线/环形等),适合 stroke-draw 动画
- CSS 变量体系完整(`--parchment` / `--brand` / `--serif` 等),便于扩展动效 token

### 编辑器兼容性
- HTML 演示台用 `LiveFrame` 加载 HTML,**脚本保留存活**,通过 postMessage 通信
- 编辑器支持文本改、位移、缩放,导出时 inline style 烘焙进文件,原脚本和结构不变
- 结论:JS 动效在编辑器中完全兼容,不需要特殊处理

## Proposed Changes

### 改动 1:kami-nextppt-deck.html 补动效层

**文件**: `apps/web/public/kami-nextppt-deck.html`
**做什么**: 在现有 `<style>` 末尾追加动效 CSS + 在 `</body>` 前追加 ~40 行 vanilla JS
**为什么**: 旗舰模版是用户第一眼看到的,必须展示"HTML 不只是静态排版"的体感差异
**具体动效设计**:

1. **封面匠心之轮**(P0 视觉冲击):
   - 外圈刻度环: `@keyframes spin-slow` 60s 线性无限旋转
   - 中心三层光晕: `@keyframes halo-pulse` 3s ease-in-out 交替缩放+透明度
   - 4 条径向线: `@keyframes line-draw` stroke-dashoffset 从 100→0,1.2s,依次延迟

2. **每页入场编排**(scroll-triggered reveal):
   - JS: `IntersectionObserver` threshold 0.15,slide 进入视口时加 `.is-visible` class
   - CSS: `.slide:not(.is-visible) .reveal` → `{ opacity:0; transform:translateY(24px) }`
   - CSS: `.slide.is-visible .reveal` → `{ opacity:1; transform:none; transition:opacity 0.6s var(--ease), transform 0.6s var(--ease) }`
   - 子元素用 `transition-delay` 依次延迟(0s / 0.1s / 0.2s / 0.3s)
   - 需要入场的元素加 `class="reveal"`,标题/正文/图表/数据卡分别延迟

3. **SVG 图表绘制动画**:
   - 焦点 path/line: `stroke-dasharray: pathLength; stroke-dashoffset: pathLength → 0`,2s ease-out
   - 触发时机: 同 IntersectionObserver,slide 可见时触发
   - 适用: 折线图路径、架构图连线、流程图箭头

4. **hover 微交互**:
   - Featured Card / Metric 卡: `transition: transform 0.2s, box-shadow 0.2s`,hover 时 `translateY(-3px)` + shadow 加深
   - 不影响编辑器(编辑模式下 hover 无副作用,inline style 优先级更高)

**JS 代码骨架**(追加到 `</body>` 前):
```html
<script>
(function(){
  var io = new IntersectionObserver(function(entries){
    entries.forEach(function(e){
      if(e.isIntersecting){
        e.target.classList.add('is-visible');
        // 触发该 slide 内 SVG path 的 draw 动画
        e.target.querySelectorAll('svg .draw-path').forEach(function(p){
          p.style.animation = 'path-draw 2s var(--ease) forwards';
        });
      }
    });
  }, { threshold: 0.15 });
  document.querySelectorAll('.slide').forEach(function(s){ io.observe(s); });
})();
</script>
```

**约束**:
- 不引入 GSAP / Motion / 任何外部 JS 库
- 全部 CSS @keyframes + 1 个 IntersectionObserver
- `prefers-reduced-motion: reduce` 时关闭所有动画
- 不改变现有 HTML 结构,只在元素上加 `class="reveal"` 和 SVG path 上加 `class="draw-path"`

### 改动 2:kami 模版 prompt 补 Motion 章节

**文件**: `apps/web/src/data/templates.ts` (id: `nextppt-kami` 的 prompt 字段)
**做什么**: 在现有 `08 · Inline SVG Charts` 和 `Anti-Patterns` 之间,插入 `09 · Motion & Interaction` 章节
**为什么**: 让用户复制 kami prompt 给 AI 时,AI 生成的 HTML 自带动效规范,而非纯静态
**章节内容**:

```
────────────────────────────────────────
09 · Motion & Interaction 动效与交互
────────────────────────────────────────
HTML 相比 PPT 的核心优势是"活的"。每个 .slide 进入视口时,其子元素应依次入场:
  · 标题/正文/图表/数据卡加 class="reveal",默认 opacity:0; transform:translateY(24px)
  · .slide.is-visible .reveal → opacity:1; transform:none; transition:opacity .6s ease, transform .6s ease
  · 子元素用 transition-delay 依次延迟(0s / .1s / .2s / .3s),形成编排感
  · 触发方式:页尾 <script> 用 IntersectionObserver(threshold:0.15)给 .slide 加 .is-visible

封面签名动效:
  · 匠心之轮外圈刻度: @keyframes spin 60s linear infinite
  · 中心光晕: @keyframes pulse 3s ease-in-out alternate(scale + opacity)
  · 径向线: stroke-dashoffset 从全长→0,1.2s,依次延迟

SVG 图表绘制:
  · 焦点 path/line 加 class="draw-path"
  · stroke-dasharray:1000; stroke-dashoffset:1000 → 0,2s ease-out
  · slide 可见时由 JS 触发 animation

hover 微交互:
  · Featured Card / Metric: hover translateY(-3px) + shadow 加深,transition .2s

约束:
  · 不引入外部 JS 库(GSAP/Motion 等),只用原生 CSS @keyframes + IntersectionObserver
  · 全部动效在 <style> 和 <script> 内,不外链
  · @media (prefers-reduced-motion: reduce) { animation:none; transition:none; .reveal{opacity:1;transform:none} }
  · 脚本总量不超过 60 行 vanilla JS
```

同时在 Anti-Patterns 末尾追加:
```
✗ 引入 GSAP / Motion / 外部动画库
✗ 动效无 prefers-reduced-motion 降级
✗ 页面一加载就全量播放动画(必须 scroll-triggered)
```

### 改动 3:通用 prompt 补动效段

**文件**: `apps/web/src/i18n/locales/zh/prompt.ts` (generate 字段) + `apps/web/src/i18n/locales/en/prompt.ts`
**做什么**: 在现有 `【内容要求】` 和末尾 `请现在直接输出…` 之间,插入 `【动效与交互(建议)】` 段
**为什么**: guide 页的通用 prompt 是用户最常用入口,补上后用户生成的 HTML 自带动效,修复"生成→编辑→发现没动画"的期望落差
**内容**:

```
【动效与交互（建议，让 HTML 真正区别于 PPT）】
- 每个 .slide 进入视口时,子元素依次淡入上浮:
  · 默认 .reveal { opacity:0; transform:translateY(24px) }
  · .slide.is-visible .reveal { opacity:1; transform:none; transition:opacity .6s,transform .6s }
  · 用 transition-delay 做依次延迟(0s/.1s/.2s/.3s)
- 页尾加一段 <script>(约 10 行):
  · 用 IntersectionObserver(threshold:0.15)监听每个 .slide,进入视口时加 .is-visible
- 封面页可加签名动效(旋转/脉冲/绘制),但不要每页都堆砌
- @media (prefers-reduced-motion: reduce) 下关闭所有动画
- 不引入外部 JS 库,只用原生 CSS + IntersectionObserver
```

定位为"建议"而非"必须",避免 prompt 过长吓退用户,同时给 AI 明确的动效生成指引。

### 改动 4:英文 prompt 同步

**文件**: `apps/web/src/i18n/locales/en/prompt.ts`
**做什么**: 将改动 3 的动效段翻译为英文,保持结构一致
**因为**: en/prompt.ts 是 zh/prompt.ts 的 typed mirror,必须同步

## Assumptions & Decisions

1. **范围决策**: 只做 kami + 通用 prompt,不铺全部 11 个模版。理由:先验证体感再铺开,避免大量改动后才发现动效风格不统一。
2. **技术路线决策**: CSS + vanilla JS,不用 GSAP。理由:① 编辑器兼容(脚本保留存活);② AI 生成稳定性(原生 API 比 GSAP 语法更不容易出错);③ HTML 体积可控;④ 符合"自包含 HTML"约束。
3. **不新建独立动效模版**: 不创建并列的"动效模版集",而是给现有模版加动效层。理由:避免"动效是特殊模版才有的"认知,动效应成为 HTML 的标配。
4. **prompt 定位为"建议"**: 通用 prompt 里的动效段用"建议"而非"必须",防止 prompt 过长。kami 模版 prompt 里用"必须",因为 kami 是旗舰。
5. **不修改 TemplateItem 接口**: 不新增 `motionPrompt` 字段,动效规范直接内嵌在现有 `prompt` 字段的新章节里。理由:保持接口简洁,避免详情页需要额外 UI。
6. **不修改 TemplatesPage / GuidePage 的 UI**: 动效只在 HTML sample 和 prompt 文本里,前端组件不需要改动。

## Verification Steps

1. **本地预览**: dev server 打开 `/templates/nextppt-kami` → 点击"在编辑器打开" → 确认滚动时各页元素依次入场、封面匠心之轮旋转、SVG 图表绘制动画、hover 卡片上浮
2. **编辑器兼容**: 在 HTML 演示台打开改后的 kami HTML → 进入编辑模式 → 改文字/拖元素 → 导出 → 确认导出的 HTML 保留 `<script>` 和 `<style>` 动效,inline style 修改也保留
3. **reduced-motion**: 系统设置开启"减少动态效果" → 确认所有动画停止,元素直接显示
4. **prompt 验证**: 复制 kami prompt → 发给 AI → 确认 AI 生成的 HTML 包含 IntersectionObserver + reveal class + CSS 动效
5. **通用 prompt 验证**: 复制 guide 页 prompt → 发给 AI → 确认 AI 生成的 HTML 有动效段(至少有 IntersectionObserver)
6. **类型检查**: `npx tsc --noEmit` 通过
7. **部署**: `./scripts/deploy-web.sh` + smoke test 通过
